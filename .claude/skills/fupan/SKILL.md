# fupan — 每日复盘 → 次日剧本

## 用途

每日收盘后（或盘后任意时间）跑一次，把高手复盘 5 步框架落地为一份**「次日剧本.md」**——三套应对预案（继续走强 / 分歧震荡 / 全面走弱），每套含**触发信号 + 操作 + 仓位**。

**核心理念**（对齐用户"少交易+严纪律"）：不预测涨跌，只做"信号触发才动手"的应对；用工具拿客观数据，脑力留给主观研判；复盘效率 > 时长。

## 与现有工具的边界（不重复造轮子）

| 工具 | 职责 | 关系 |
|------|------|------|
| `trade_review.py` | 周复盘，**盯账户纪律**（补仓/大单/胜率）→ 向内 | 互补，不重叠 |
| **`fupan`（本 skill）** | 每日，**盯市场 + 次日预案** → 向外 | 本 skill |
| `market_regime` | 市况总开关 🔴/🟡/🟢 | 第 0 步复用其核心函数 |
| `zhuxian` | 主线板块 Top N | 第 2 步读其 `zx_{date}.json` |
| `qsht-agent` / `eval-stock` | 选股漏斗 / 个股体检 | 第 5 步选接力标的时调 |

> 本 skill 的细化规则依据：[docs/2026-07-19-高手选股复盘思路.md](docs/2026-07-19-高手选股复盘思路.md) 复盘篇各节「📊 实战量化标准」表。

## 运行方式

```bash
python .claude/skills/fupan/main.py                  # 默认，自包含运行
python .claude/skills/fupan/main.py --note "..."     # 加备注
python .claude/skills/fupan/main.py --top 3          # 主线只看 Top 3
python .claude/skills/fupan/main.py --strict         # 门禁: 第3/4步占位符未填→报告顶部红色banner+exit=1
```

- **自包含**：`main.py` 自己拉指数 K 线（含成交额）+ 复用 `market_regime` 核心函数算市况，不依赖外部脚本先跑。
- **数据源（指数K线）**：优先读本地招商证券 vipdoc（通达信 `.day`，`scripts/local_kline.py`，快/不被封），本地无数据才 fallback 新浪。前提：需在招商证券客户端「盘后下载日线」，否则当日缺数据（会自动降级走新浪）。指数无除权问题，本地不复权价直接可用。
- **可选增强**：若先跑过 `/zhuxian`（产出 `.claude/skills/zhuxian/data/zx_{date}.json`），第 2 步会展示主线板块并判定阶段；**未跑则降级**为"建议先跑 /zhuxian"，其余步骤照常。
- 全程约 10 秒–2 分钟（本地源命中时最快~10s：3 指数K线本地 + 本地全市场宽度1-2s；降级网络源时较久）。

## 5 步流程（对应文档复盘篇量化标准）

### 第 0 步｜市况总开关
复用 `market_regime` 核心函数重算 🟢进攻/🟡防守/🔴退守（趋势分+宽度分）。**这是"要不要操作"的总指挥**：
- 🔴退守 → 剧本直接落「空仓观望」，不开新仓
- 🟡防守 → 半仓做个股，只做最强信号
- 🟢进攻 → 正常仓位按 qsht 体系选股

> ⛔ **CHECKPOINT · 退守市强制空仓**：第0步市况=🔴退守时，第5步三套剧本的仓位栏**强制锁「🔴空仓」**，并在报告顶部明示"今日不开新仓"。此为铁律，**不因用户想买票而放宽**——对齐"少交易+严纪律"（退守市 80% 大亏发生于此）。

### 第 1 步｜大盘状态（不看涨跌看状态）
自拉上证/沪深300/创业板日K，按文档量化标准判三维度：
- **结构**：MA5/10/20 多头排列=上升 / 空头排列=下跌 / 缠绕=震荡 / 触近前高=反弹末尾⚠️
- **量能**：当日成交额 vs 前 5 日均量，>1.2×=放量 / <0.8×=缩量 / 之间=平量
- **权重 vs 题材**：上证强+创业板弱=权重护盘(虚涨) / 创业板强=题材主导

### 第 2 步｜主线与阶段（资金在哪抱团）
读 `zhuxian` 的 `zx_{date}.json` 展示 Top N 主线板块；读近 7 日 `zx_*.json` 判**主线阶段**（启动/加速/分歧震荡/退潮）——基于 Top1 趋势得分变化初判，数据不足时诚实标注。

### 第 3 步｜强势股拆解（⛔ CHECKPOINT · 人工研判必填）
脚本自动扫描连板梯队（`fupan_strong_scan`，本地vipdoc）：涨停总数 / 首板 vs 连板 / 连板高度前 8（带客观标签：封板强度·量比·振幅·一字，**+ 成色(pattern) 列：形态/量能/板块联动→建议归类，来自 `scripts/pattern_label.py`，标「参考·需人工确认」**）。**人工只填三维度拆解**：从连板高度前 N 挑，判首板属性 / 连板健康度 / 分歧节点。扫描模块不可用时降级为纯 checklist。

### 第 4 步｜失败案例·市场层面（⛔ CHECKPOINT · 人工研判必填）
脚本给市场宽度信号（涨停/跌停家数、涨停稀少/跌停潮预警）+ 自动扫描失败模式（`fupan_failure_scan`，本地vipdoc）：炸板 / 断板(昨涨停今跌) / 高位长上影 / 大跌名单。**人工只填归类根源**：追高 / 模式外冲动 / 环境恶劣。**自己账户的失败交易由 `trade_review.py` 周复盘覆盖，本步只看市场层面。**

### 第 5 步｜次日三套剧本
综合市况 + 大盘 + 主线阶段，套三情景模板（A 继续走强 / B 分歧震荡 / C 全面走弱），每情景含**触发信号 + 操作 + 仓位**，仓位随市况自动联动（🟢正常/🟡半仓/🔴空仓）。

## 输出

报告保存在 `.claude/skills/fupan/output/{日期}.md`，结构：
```
# 次日剧本 · YYYY-MM-DD
## 0. 市况总开关：🟡防守市
## 1. 大盘状态：结构/量能/权重vs题材（表格）
## 2. 主线与阶段：Top板块 + 阶段初判
## 3. 强势股拆解：连板梯队(客观) + 三维度拆解[人工研判]
## 4. 失败案例：宽度+炸板/断板/大跌(客观) + 归类[人工研判]
## 5. 🎬 次日三套剧本（A/B/C 表格，含触发信号+操作+仓位）
```

> ⛔ **交付前 CHECKPOINT · 主观部分必填**：第3步（强势股拆解）与第4步（失败归类）的 checklist 必须**各至少填 1 条研判**，否则剧本视为未完成——客观数据 + 人工研判缺一不可，空着交差属反例（见反例黑名单）。

运行完成后，用 Read 工具读取报告文件并向用户展示。

## 边界条件

| 场景 | 处理方式 |
|------|---------|
| `market_regime` import 失败 | **停止执行+提示修复**（无市况总开关，剧本无意义） |
| 全市场宽度三源（本地vipdoc→东财→新浪）均无**最近交易日**数据 | **停止执行+打印各源失败原因**（宽度是市况总开关关键输入，宁停勿用过期/错误数据）；排查：①招商证券客户端盘后下载最近交易日日线 ②网络可达性(东财push2/新浪) |
| 宽度接口返回**脏数据**（东财偶发只返回部分股票，中位/涨跌比与指数严重背离，如创业板 −7% 却中位 +9.98%） | main.py 第4步已加宽度-指数背离校验（`abs(med)>8` 或 指数与中位数反向），触发时标 ⚠️"以指数为准，忽略本行宽度"，且不显示会误导的涨停稀少/跌停潮结论。**接入新宽度源必须保留此校验** |
| 未跑 `/zhuxian`（无 `zx_{date}.json`） | 第 2 步标"建议先跑 /zhuxian"，主线阶段判为"数据不足" |
| 历史 zx 不足 3 日 | 主线阶段标"数据不足(需积累多日)"，仍展示当日 Top 板块 |
| 非交易日 | 新浪返回最近交易日数据，正常产出（标注日期） |
| 指数 K 线拉取失败 | 该指数标"取数失败"，不阻断其他指数 |

## ❌ 反例黑名单

| 不要 | 原因 | 正确做法 |
|---|---|---|
| 把剧本当涨跌预测 | 剧本是"应对预案"，不是"明天必涨/必跌" | 看 A/B/C 三情景的触发信号，触发哪个做哪个 |
| 信号未到就动手 | 违背"少交易+严纪律" | 退守市→直接空仓；分歧期→不追加，等信号 |
| 用本 skill 复盘自己账户 | 账户纪律是 `trade_review.py` 的职责 | 周末跑 trade_review 盯补仓/大单/胜率 |
| 跳过第 0 步市况直接选股 | 🔴退守市 80% 大亏发生于此 | 市况总开关优先，🔴→空仓 |
| 当第 3/4 步 checklist 空着就交差 | 主观研判才是复盘精华 | 强势股拆解 + 失败归类必须填，哪怕只写一句 |

## 注意

- 主线阶段判定为**小样本初判**（基于 Top1 趋势得分变化），非精确信号；精确阶段需多日涨停家数 + 龙头连板数据，结合人工研判。
- 第 3 步（强势股拆解）与第 4 步（失败归类）：**客观数据已自动**（`fupan_strong_scan` 出连板梯队 / `fupan_failure_scan` 出炸板·断板·大跌名单，均本地vipdoc），**主观结论仍由人填**——三维度拆解与归类是设计上的人工研判，非功能缺失。扫描模块不可用→降级纯 checklist，不阻断。
- 数据源：① 指数K线优先本地招商证券 vipdoc（`scripts/local_kline.py` 读通达信 `.day`），本地无数据 fallback 新浪（`CN_MarketData.getKLineData`，含成交额）；② **宽度复用 `market_regime`，三源降级链：本地vipdoc全市场（`local_kline.fetch_local_breadth`，1-2s/最全~6700只/收盘数据，需客户端盘后下载最近交易日日线）→ 东财 push2 全市场（直连偶发被封/脏数据时跳过）→ 新浪全市场 hs_a（并发~9s）**。三源都取不到**最近交易日**全市场数据 → **停止执行**（宽度是市况总开关关键输入，宁停勿错）。本地源校验 `latest_date` 距今≤4天（=最近交易日，覆盖周末/短假）+ 覆盖≥3000，防用过期/残缺数据。本 skill 不自建宽度接口，跟随 `market_regime` 演进。
- 剧本为客观数据 + 规则模板，**不构成投资建议**；主观部分需结合自身仓位与心态研判。
