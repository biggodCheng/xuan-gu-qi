# Q2业绩展望器

基于 **2026Q1 已披露业绩**,推断一只 A 股的 **Q2 业绩走向**,产出定性展望 + 信号面板。

## 它解决什么问题

光看 Q1 净利润增速容易误判:基数陷阱(去年同期极低→增速虚高)、一次性损益、增长是否持续都看不出来。本 skill 用**两个信号**判断 Q2,把判断依据摊开:

- **信号A 同比势头(加速度)**:Q1 单季同比 vs 去年 Q4 单季同比 → 增长在加速还是减速
- **信号B 营收-净利背离**:Q1 营收同比 vs 净利同比 + 毛利率变化 → Q2 利润率方向

> 克制原则:公开季报不足以支撑精确预测。本 skill 只给**方向(偏正/中性/偏负)+ 依据 + 置信度**,绝不甩"-30%"这种伪精确数字。

## 使用方式

### 单只查询
输入 `/q2zhanwang <股票代码或名称>` 触发。
- `/q2zhanwang 比亚迪` — 按名称
- `/q2zhanwang 002594` — 按代码
- `/q2zhanwang 600519` — 贵州茅台

### 批量查询
输入 `/q2zhanwang <stocks.json>`,读取 `zhangting`/`chuangxingao` 等输出的股票列表(`stocks[].code`),批量推断并按展望排序。

## 执行步骤

1. 确认依赖已安装:
   ```bash
   cd .claude/skills/q2zhanwang && pip install -r requirements.txt
   ```

2. 运行(单只):
   ```bash
   cd .claude/skills/q2zhanwang && python main.py "<股票代码或名称>"
   ```
   或批量:
   ```bash
   cd .claude/skills/q2zhanwang && python batch_query.py <stocks.json>
   ```

3. 脚本会:
   - 解析股票代码(名称→代码,东方财富 searchapi)
   - 拉取近 9 期财报(东方财富 datacenter,累计口径)
   - **单季化**后自算单季同比(见下文,不能用接口自带同比)
   - 算势头信号 A、背离信号 B → 合成 verdict 与置信度
   - 单只输出 JSON 到 stdout;批量写 `data/batch_<date>.json`

4. 读取输出,向用户展示:
   - Q2 展望(verdict + 置信度)
   - Q1 基础数据(净利/营收同比、归母净利、毛利率)
   - 两个信号的 direction + note
   - 总结

## 关键机制:为什么必须单季化(解读前必读)

接口每期返回的是**累计**口径(中报=上半年、三季报=前三季、年报=全年),且**自带同比随报告期变口径**:
- 一季报的同比 = Q1 单季同比 ✓
- 年报的同比 = 全年同比 ✗(不是 Q4 单季)

直接拿接口同比跨期比较会错。故脚本统一**自算单季同比**:`Q单季 = 本期累计 − 上一期累计`,再算 `(本期单季 − 去年同期单季)/|去年同期单季|`。

例:比亚迪 2025Q4 接口给全年同比 -18.97%,但**单季化**后 2025Q4 单季同比 = -38.17%(326.19年报 − 233.33三季报 = 92.86亿单季)。两者完全不同。

## verdict 判定矩阵

| | A 加速 | A 持平 | A 减速 |
|---|---|---|---|
| **B 改善** | 偏正 | 偏正/中性 | 中性 |
| **B 同步** | 偏正 | 中性 | 偏负 |
| **B 承压** | 中性 | 偏负 | **偏负** |

- **confidence**:两信号同向→高;矛盾/含持平→中;数据缺期/单季化异常→低。

## 边界条件与失败处理

每行按「触发条件 / 一线处理 / 仍失败兜底」三段式:

| 触发条件 | 一线处理 | 仍失败兜底 |
|---|---|---|
| 股票代码/名称不存在 | 提示"未找到该股票" | — |
| 2026Q1 尚未披露 | "该股 2026Q1 未披露",给最近一期 | — |
| 缺 2025 年报(算不出 Q4单季) | 信号A降级"数据不足",只给B,confidence→低 | — |
| 新股(无 2025Q1,算不出同比) | verdict="数据不足",列出已有数据 | — |
| 单季化异常(负值/单季>累计,疑重述) | 标注"数据可能修订",降 confidence | — |
| 去年同期单季基数过小 | 标"基数过小,增速失真",confidence→低 | — |
| 接口请求失败 | 重试 1 次 | "数据获取失败,稍后重试" |
| 批量输入文件格式错 | 提示格式异常 + 示例 | — |

## ⚠️ 正确解读(局限)

| 现象 | 正确解读 |
|---|---|
| 高净利增速却判偏负(如宁德 +48%→偏负) | 增长在**减速**(势头信号),Q1高增但Q2可能回落。这正是本 skill 比单看增速有价值之处 |
| verdict=中性 | 两信号一正一负或都持平,**不等于"没问题"**,要看 signals 细分方向 |
| confidence=低 | 数据缺期或单季化异常,**结论仅供参考**,勿重仓决策 |
| 仅归母未扣非 | 一次性损益(补贴/资产处置)会扭曲,高增速应再看扣非(本 skill 数据源不含) |

### 解读操作流

1. 先看 `verdict` + `confidence`——confidence 低则结论打折
2. 看 `signals.momentum.direction`:减速≠业绩差,但预示 Q2 比Q1弱
3. 看 `signals.divergence.direction`:利润承压预示 Q2 净利率下行
4. 结合 `q1.parent_netprofit_prev_yi` 判断基数效应

### ❌ 不要做

- **不要把 verdict 当精确预测**——它是方向判断,不是 Q2 净利数字
- **不要忽视 confidence**——低置信度的偏负/偏正不可靠
- **不要在非 Q1 时点强用**——中报/三季报披露后,最新报告期不再是 Q1,展望失去意义(脚本会提示)
- **不要仅凭 verdict 买卖**——归母未扣非、单季化依赖未重述数据,需结合其他信息
